# LocalizationGenerator

An SPM `BuildToolPlugin` that automatically converts a CSV file of translations into
`Localizable.strings` files for every locale — re-generated on every Xcode / `swift build`
invocation so your strings are always in sync with the source CSV.

## Features

- **Zero boilerplate** — drop one CSV file into your target, the plugin does the rest
- **Runs at build time** — powered by SPM's `BuildToolPlugin` / `prebuildCommand`, so generated files are ready before compilation
- **RFC 4180-compliant CSV parser** — handles quoted fields, embedded commas, embedded newlines, escaped quotes, Windows line-endings, and BOM
- **Xcode + SwiftPM** — works in both SPM packages and Xcode projects (via `XcodeBuildToolPlugin`)
- **No external dependencies** — zero transitive deps added to your project

## Installation

### Swift Package Manager

Add the package to your `Package.swift`:

```swift
dependencies: [
    .package(url: "https://github.com/<your-username>/LocalizationGenerator.git", from: "1.0.0")
],
```

Then apply the plugin to any target that should generate strings:

```swift
.target(
    name: "MyApp",
    plugins: [
        .plugin(name: "LocalizationPlugin", package: "LocalizationGenerator")
    ]
)
```

### Xcode project

1. **File → Add Package Dependencies…** and enter the repository URL.
2. In your app target's **Build Phases**, add `LocalizationPlugin` under **Run Build Tool Plug-ins**.

## CSV format

The first row must be the header, followed by one row per localizable string:

```
id,key,<locale-1>,<locale-2>,...
```

| Column | Description |
|---|---|
| `id` | Human-readable identifier — written as a `/* comment */` in the `.strings` file |
| `key` | The string key used in `NSLocalizedString` / `String(localized:)` calls |
| locale columns | One column per locale code (`en`, `fr`, `es`, `de`, …). Empty cells are silently skipped. |

### Example — `Localizations.csv`

```csv
id,key,en,fr,es,de
app_name,app.name,My App,Mon App,Mi App,Meine App
welcome_title,welcome.title,Welcome!,Bienvenue !,¡Bienvenido!,Willkommen!
button_cancel,button.cancel,Cancel,Annuler,Cancelar,Abbrechen
greeting_format,greeting.format,"Hello, %@!","Bonjour, %@ !","¡Hola, %@!","Hallo, %@!"
error_network,error.network,Network error. Please try again.,Erreur réseau. Veuillez réessayer.,Error de red. Inténtalo.,Netzwerkfehler. Bitte erneut.
```

> Cells that contain commas or newlines must be wrapped in double-quotes, as per RFC 4180.
> Use `""` to represent a literal quote character inside a quoted field.

## Output

For the CSV above the plugin generates:

```
<plugin-work-dir>/GeneratedLocalizations/
    en.lproj/Localizable.strings
    fr.lproj/Localizable.strings
    es.lproj/Localizable.strings
    de.lproj/Localizable.strings
```

**`en.lproj/Localizable.strings`**
```strings
// Generated by LocalizationTool — do not edit manually.

/* app_name */
"app.name" = "My App";

/* welcome_title */
"welcome.title" = "Welcome!";

/* button_cancel */
"button.cancel" = "Cancel";

/* greeting_format */
"greeting.format" = "Hello, %@!";

/* error_network */
"error.network" = "Network error. Please try again.";
```

## Usage in code

The generated files are standard `.strings` resources — use them exactly as you would hand-written ones:

```swift
// Swift
let appName = String(localized: "app.name")
let greeting = String(localized: "greeting.format")  // use with String(format:) for %@ substitution

// Objective-C
NSString *cancel = NSLocalizedString(@"button.cancel", nil);
```

## Running the CLI directly

The underlying tool can also be invoked standalone (useful for CI pre-checks or scripts):

```bash
swift run LocalizationTool \
  --input path/to/Localizations.csv \
  --output path/to/output \
  --verbose
```

## How it works

```
Xcode / swift build
       │
       ▼
LocalizationPlugin (BuildToolPlugin)
  • scans target source directory for *.csv files
  • registers a prebuildCommand for each CSV found
       │
       ▼
LocalizationTool (CLI binary)
  • CSVParser    — tokenizes CSV respecting RFC 4180 quoting rules
  • StringsFileGenerator — writes <locale>.lproj/Localizable.strings
       │
       ▼
Generated files added to module bundle as localized resources
```

The plugin uses `prebuildCommand`, which means the `.strings` files are written **before** compilation starts — no extra build phases required.
